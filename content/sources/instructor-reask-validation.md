## Summary

Instructor's page on validating LLM output with Pydantic and asking again when it fails. You put rules on the Pydantic model (in code, or checked by another LLM call); when the parsed output breaks a rule, Instructor appends the model's reply and the error message to the conversation and calls again, up to `max_retries`. Validators can also get runtime context, like the source text, to check a quote really appears in it.

## Key claims

- The framing: self-correction is just validation with good error messages. "we can view them as validation errors with clear error messages that the system can use to self-correct." (Validation and Reasking, intro)
- Code-based validation: a Pydantic validator raises `ValueError` (example: a name must contain a space). (Code-based Validation Example)
- LLM-based validation: `llm_validator("don't say objectionable things", ...)` makes another model check the value, and "the error message is generated by the LLM, not the code". (LLM-Based Validation Example)
- `max_retries` sets how many times to re-ask. "you can use the max_retries parameter to set the number of times you can reask the model to correct the output." (Using Reasking Logic)
- It catches two kinds of failure. "Pydantic Validation Errors (code or llm based)" and "JSON Decoding Errors (when the model returns a bad response)" (Using Reasking Logic)
- Example: a validator requires an uppercase name, the input is lowercase, `max_retries=2`. (Step 1, Step 2)
- What a retry is: on `ValidationError`, append the assistant message and a user message with the error, then call again. The message text is "Please correct the function call; errors encountered:\n{e}". (What happens behind the scenes?)
- Context validation: pass the source document in `context` so a validator can check a `supporting_quote` exists in it; "If the LLM generates a quote that doesn't exist in the source, validation fails and the model is re-asked" (Using Context for Dynamic Validation)
- Error messages cost tokens: Pydantic adds a URL to each error, and Instructor offers `disable_pydantic_error_url()` to strip it. (Optimizing Token usage)

- The retry loop: call, parse, validate, on error append reply + error and call again, stop at max_retries.
