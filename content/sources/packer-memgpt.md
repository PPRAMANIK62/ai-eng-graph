## Summary

The paper that framed agent memory as an operating-system problem. The context window is like RAM and outside storage is like disk, and the model itself moves data between them by calling functions. The prompt is split into fixed instructions, a small editable "working context", and a queue of recent messages; older messages go to a searchable message database, and there's a separate archival store. Revised 2024-02-12. The HTML version (v2) was used for the section details.

## Key claims

- The problem. LLMs "are constrained by limited context windows, hindering their utility in tasks like extended conversations and document analysis." (Abstract)
- The idea: "virtual context management, a technique drawing inspiration from hierarchical memory systems in traditional operating systems that provide the appearance of large memory resources through data movement between fast and slow memory." (Abstract)
- Main context has three parts. "The prompt tokens in MemGPT are split into three contiguous sections: the system instructions, working context, and FIFO Queue." (Section 2)
- Working context is "A fixed-size read/write block of unstructured text, writeable only via MemGPT function calls." (Section 2)
- External context. "External context refers to any information that is held outside of the LLMs fixed context window." (Section 2)
- Recall storage is the message database; archival storage is a "read/write database storing arbitrary length text objects". (Section 2)
- The model moves the data itself. "MemGPT orchestrates data movement between main context and external context via function calls that are generated by the LLM processor." (Section 2)
- Memory pressure warning when prompt tokens pass a "warning token count" (e.g. 70% of the context window); at the "flush token count" (e.g. 100%) the queue manager evicts messages and "generates a new recursive summary using the existing recursive summary and evicted messages." (Section 2, queue manager)
- Warning purpose: the queue manager inserts a system message "warning the LLM of an impending queue eviction (a 'memory pressure' warning) to allow the LLM to use MemGPT functions to store important information contained in the FIFO queue to working context or archival storage". (Section 2, queue manager)
- Evicted messages "are no longer in-context and immediately viewable to the LLM, however they are stored indefinitely in recall storage and readable via MemGPT function calls." (Section 2, queue manager)
- Evaluated on document analysis and multi-session chat, where agents "remember, reflect, and evolve dynamically through long-term interactions with their users." (Abstract)
