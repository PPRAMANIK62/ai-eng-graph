## Summary

The DOMINO paper. It argues that much of the accuracy loss blamed on constrained decoding comes from bad engines: the grammar works in characters or grammar pieces, the model works in subword tokens, and a naive engine that only allows tokens matching the next grammar piece forces the model into token sequences it would never pick. DOMINO allows tokens that span several grammar pieces ("bridge tokens"), and on a JSON version of GSM8K this recovers the lost accuracy. Read the abstract, introduction and section 2 in the HTML version (v1; the page is dated 2024-02-07, the arXiv id is from 2024-03).

## Key claims

- The headline. "many of them also significantly impair task accuracy, if they do not correctly align the underlying LLM sub-word vocabularies with external constraints." (abstract)
- The key challenge is token misalignment. "Since LLM sub-word token do not align directly with most given syntactic constraints, the key challenge in constrained decoding is to interface the LLM vocabulary with a syntactic constraint" (Key Challenge: Token Misalignment)
- The Figure 1 example: unconstrained, the model writes a token that is a space plus a quote; a naive JSON constraint only allows a lone quote or whitespace, so the model picks a tab instead, and the output drifts into high-perplexity tokens. "naive constraining does not account for bridge tokens that may span multiple parser terminals in the underlying grammar (e.g., whitespace and double quotes, in this example)." (Key Challenge)
- Definition of the goal. "We consider a constrained decoding method minimally invasive, if every valid output that can be generated by an unconstrained model (for any given prompt), is also generated by the constrained model, given the same prompt." (Definition 2.1)
- The number: on JSON-encoded GSM8K (five-shot, Mistral 7B), naive constraining drops accuracy "from 41.5% in the unconstrained case to 30.8%, while minimally invasive constraining actually achieves a slight increase in accuracy to 41.8%". (2, after Definition 2.1)
- Regex-only constraints mostly avoid the problem; it bites with grammars and templates. Regex-based decoding "typically does not suffer from the token misalignment problem" (Regex-Based)
- Templates that insert fixed text with an outside tokenizer also misalign: template outputs had perplexity 24.50 to 26.75 vs 4.17 unconstrained. (Template-Induced Misalignment)
- Fixed template text can be inserted without running the model, which saves forward passes. "templated tokens can be added deterministically during generation, without invoking the LLM, thereby requiring less model forward passes." (Template-Based Approaches)
- Speed claim: "virtually no overhead and in some cases even almost 2× speedup over unconstrained decoding" using precomputation and speculative decoding. (abstract)

## My notes

- Authors built LMQL, a competing constrained-generation tool, so they also have a stake. But their point supports constrained decoding done well, not the claim that it hurts.
- Explains why Let Me Speak Freely and the rebuttals can both see real numbers: the engine matters.
